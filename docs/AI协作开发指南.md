# AI 协作开发指南

这份指南用于让 AI 帮助迭代《月影古堡》，同时尽量避免一次修改破坏现有功能。

## 1. 给 AI 的项目背景

可以先发送以下说明：

> 我在开发一个原创 2D 像素风横版动作游戏《月影古堡 Moonlit Keep》。项目是原生 HTML/CSS/JavaScript + Canvas 的 PWA，不使用游戏引擎。主要文件是 `index.html`、`manifest.webmanifest`、`sw.js`、`icon.svg`。游戏支持 Android 触屏与键盘输入，有移动、跳跃、平台、挥鞭、灵击、普通敌人、Boss、生命/灵力 HUD 和胜负界面。请保留现有功能，优先小范围修改，并说明修改的文件、原因和验证步骤。

## 2. 推荐需求格式

每次只指定一个主要目标：

1. **目标**：希望玩家看到/做到什么。
2. **当前问题**：具体表现、复现步骤。
3. **限制**：哪些操作、界面、数据结构不能破坏。
4. **验收条件**：如何判断完成。
5. **交付要求**：完整文件、差异说明、测试清单和版本记录。

例如：

> 目标：让挥鞭攻击更有手感。当前问题：动画结束前看起来已经碰到敌人，但有时没有伤害。请先分析 `drawHero()`、`attackHitbox()`、`applyWhipHits()` 的关系，再提出最小修改。不要重写整个游戏。完成后列出变更点，并检查左右朝向、单次攻击只命中一次、Boss 也可受伤。

## 3. 可复用提示词

### 新增角色动画

> 请为当前玩家增加原创逐帧像素动画方案。先评估继续使用 Canvas 几何绘制还是导入 sprite sheet 更合适。不要使用任何现有商业游戏角色或素材。保留现有碰撞盒和输入逻辑。请提供资源规格、代码修改点、回退方案和测试清单。

### 调整攻击判定

> 请检查挥鞭动画与攻击判定是否同步。列出攻击前摇、有效帧、收招的时间区间，以及攻击盒在左右朝向下的位置。确保一次挥击对同一目标最多造成一次伤害，并分别测试普通敌人与 Boss。尽量做最小修改。

### 增加新敌人

> 请在现有敌人系统中增加一种原创敌人。说明新增的数据字段、绘制分支、移动/攻击行为、碰撞和死亡处理。不要破坏现有敌人类型；请给出建议数值及测试步骤。

### 修复 Android 触控问题

> 请优先排查 Pointer Events、按钮遮挡、`touch-action`、`pointercancel` 和窗口失焦逻辑。保留键盘操作。不要只根据桌面浏览器推断手机表现；请说明哪些问题需要在真实 Android 设备验证。

### 增加新关卡

> 请基于当前世界坐标、`platforms` 数组和 `camera` 镜头机制增加一个原创关卡区域。确保物理和碰撞使用世界坐标、绘制时再应用镜头偏移。给出平台坐标、敌人配置、关卡进入条件和可达性测试清单。

## 4. 不建议的做法

- 一次要求 AI 重写整个 `index.html`，容易丢失已有功能。
- 只看代码“像是正确”就认为完成；必须运行并实际操作。
- 只修改攻击动画而不检查攻击盒，容易出现视觉与伤害不一致。
- 只在电脑上测试，就假设 Android 触控、屏幕比例和 PWA 安装一定正常。
- 改了资源却不更新 Service Worker 缓存版本，导致线上仍显示旧内容。
- 引入未经确认许可的商业游戏角色、贴图、音乐或音效。

## 5. 推荐迭代流程

1. 保存当前可运行版本或创建 Git commit。
2. 让 AI 先分析当前实现并列出计划，不急着直接重写。
3. 一次完成一个小功能。
4. 对 JavaScript 做语法检查。
5. 按玩法文档的回归清单测试。
6. 在目标 Android 设备上测试触控与横屏。
7. 检查 PWA 缓存是否需要升级。
8. 更新 README、CHANGELOG 和技术文档。
9. 发布到 GitHub Pages，确认线上版本。
