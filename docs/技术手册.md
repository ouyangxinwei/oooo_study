# 《月影古堡 Moonlit Keep》技术手册

- 文档版本：v0.2
- 项目类型：原生 Web 2D 游戏原型 / PWA
- 目标设备：桌面浏览器与 Android 手机浏览器
- 技术栈：HTML5、CSS、JavaScript、Canvas 2D、Web App Manifest、Service Worker

## 1. 系统概览

游戏不依赖框架或构建工具。主要逻辑集中在 `index.html` 的内嵌脚本中，浏览器直接解析即可运行。

```text
index.html
 ├─ HTML：HUD、Canvas、开始/结束遮罩、触屏按钮
 ├─ CSS：深色像素风界面、响应式布局、触屏按钮样式
 └─ JavaScript IIFE
     ├─ 游戏状态：玩家、敌人、Boss、投射物、平台、镜头
     ├─ 输入：Pointer Events、键盘事件
     ├─ update(dt)：状态更新、移动、碰撞、伤害、AI、HUD
     ├─ render()：清屏并绘制世界
     └─ loop()：requestAnimationFrame 驱动游戏循环

manifest.webmanifest：安装名称、启动页、横屏、图标
sw.js                  ：静态资源缓存与离线回退
icon.svg               ：PWA 图标
```

## 2. 重要文件

| 文件 | 职责 | 修改时注意 |
|---|---|---|
| `index.html` | 游戏主体与全部游戏逻辑 | 修改后检查 JS 语法、输入、碰撞和手机布局 |
| `manifest.webmanifest` | PWA 元数据 | `start_url`、`scope`、图标路径应与部署目录一致 |
| `sw.js` | 缓存静态资源 | 更新资源后应递增缓存名，例如 `moonlit-keep-v3` |
| `icon.svg` | 安装图标 | 保持 SVG 有效，图标路径与 manifest 对应 |
| `README.md` | 项目入口与快速说明 | 新增文件或功能后同步更新 |
| `docs/` | 详细技术与操作手册 | 修改系统行为后同步更新对应文档 |

## 3. 游戏坐标与渲染

- Canvas 内部逻辑分辨率：`480 × 270`。
- CSS 将 Canvas 拉伸到游戏区域，并通过 `image-rendering: pixelated` 保持像素风格。
- 世界宽度：`worldWidth = 1440`；摄像机变量 `camera` 决定世界坐标到屏幕坐标的偏移。
- 绘制世界物件时通常使用 `对象.x - camera`；物理与碰撞仍使用世界坐标。
- 地面和浮动平台在 `platforms` 数组中定义。平台的 `x/y/w` 分别表示横坐标、顶面纵坐标、宽度。

**新增物件时的关键约定：** 碰撞计算使用世界坐标；绘制时才减去 `camera`。不要在更新逻辑中提前减摄像机偏移，否则可能造成视觉位置与碰撞位置不一致。

## 4. 主循环

核心流程为：

1. `requestAnimationFrame(loop)` 请求下一帧。
2. `loop(now)` 根据时间戳计算 `dt`，并限制单帧最大步长，降低切换标签页或卡顿后物理跳变。
3. `update(dt)` 更新动画计时、输入、速度、重力、平台碰撞、敌人/Boss、投射物、镜头与 HUD。
4. `render()` 清空 Canvas，绘制背景、平台、敌人、Boss、玩家和投射物。
5. 若游戏仍在运行，则继续请求下一帧。

修改物理或攻击时间时，尽量使用 `dt` 累积时间，而不要直接假设每秒固定帧数。绘制函数尽量只负责显示，不应在其中修改重要游戏状态；当前少量受击闪白计时逻辑写在绘制路径中，后续重构时可移到 `update()`。

## 5. 核心数据结构

### 玩家 `player`

常用字段包括：

- `x/y`：世界坐标；`w/h`：碰撞盒尺寸。
- `vx/vy`：水平/垂直速度；`face`：朝向，`1` 表示右，`-1` 表示左。
- `hp/mp`：生命和灵力。
- `onGround`：是否站在平台上。
- `attackT`、`attackDuration`、`attackRange`：挥鞭计时、总时长和攻击距离。
- `attackHitIds`：本次挥击已命中的目标集合，防止同一挥击重复扣血。
- `magicT`：灵击动画计时；`invuln`：受伤后的短暂无敌计时。
- `anim`：角色动画计时；`knockback`、`knockbackVx`：击退状态。

### 普通敌人 `enemies`

每个敌人有位置、尺寸、当前/最大 HP、速度、类型 `kind`、存活状态 `alive`、攻击冷却 `cd` 等字段。绘制函数依据 `kind` 选择不同的简单像素造型。

### Boss `boss`

Boss 有独立 HP、速度、存活状态、攻击冷却和受击闪白计时。玩家进入后段区域后设置 `bossSpawned = true`，之后才参与绘制与战斗逻辑。

### 投射物 `projectiles`

投射物包含 `x/y`、水平速度 `vx`、剩余寿命 `life`。Boss 投射物使用 `hostile: true` 标记；玩家灵击不设置该标记。更新循环移动投射物、检查碰撞、扣血，并在寿命结束或离开世界后移除。

## 6. 碰撞与攻击判定

- `overlaps(a, b)`：轴对齐矩形（AABB）碰撞判断。
- `attack()`：开始一次挥击，重置本次攻击已命中集合。
- `attackHitbox()`：依据攻击进度判断当前是否处于有效帧；有效时返回攻击矩形。
- `applyWhipHits()`：遍历存活敌人与 Boss，确认攻击盒相交后扣血、闪白并施加位移。
- 玩家受伤由 `hurt(amount)` 处理，并检查无敌状态，更新生命值、击退与失败状态。

攻击动画与判定是两个相关但不同的层次：动画决定玩家看到什么；攻击盒决定哪些目标实际受伤。若调整鞭子的视觉轨迹，也要单独核对 `attackHitbox()` 的范围、垂直位置和有效帧，避免“看起来打中了但没有伤害”或“没碰到却受伤”。

## 7. 触屏与键盘输入

触屏按钮通过 `data-key` 绑定逻辑键名，并使用 Pointer Events 设置/清除状态。键盘通过 `keydown`/`keyup` 映射到同一组 `keys` 状态。

| 动作 | 键盘 | 触屏 |
|---|---|---|
| 左移 | ← / A | ◀ |
| 右移 | → / D | ▶ |
| 跳跃 | ↑ / W / 空格 | ▲ |
| 下蹲（当前为输入预留） | ↓ / S | ▼ |
| 挥鞭 | J | 挥鞭 |
| 灵击 | K | 灵击 ✦ |

新增操作时尽量复用 `keys` 状态，并测试键盘按下/松开、触屏按住、触控取消、窗口失焦等情况。

## 8. PWA 机制

- `manifest.webmanifest` 声明应用名称、启动地址、独立窗口显示模式、横屏方向和图标。
- `sw.js` 在安装时缓存入口文件、manifest 和图标；请求优先查缓存，未命中时尝试网络。
- 缓存策略简洁，适合演示项目；它不是完整的版本管理或数据同步方案。
- 部署路径若不是仓库根目录，必须确认相对路径和 GitHub Pages 的项目路径一致。
- 更新静态资源后递增 Service Worker 缓存名，并重新加载网页。若仍显示旧版本，按排障文档清理站点数据或重新安装。

## 9. 修改与验证流程

每次改动建议按以下顺序执行：

1. 备份或提交 Git commit。
2. 小步修改，避免一次重写整份 `index.html`。
3. 用 JavaScript 语法检查工具检查内嵌脚本。
4. 浏览器打开游戏，检查开始、移动、跳跃、攻击、灵击、敌人、Boss、胜负状态。
5. 在 Android 竖屏和横屏至少各检查一次布局；实际游玩建议横屏。
6. 若更新 PWA，检查 manifest、Service Worker 注册和缓存版本。
7. 更新 `README.md`、`CHANGELOG.md` 和相关文档。

## 10. 已知限制

这是学习用原型：逻辑集中在一个 HTML 文件，动画以几何像素块绘制，没有精灵图动画、完整关卡编辑器、音频、存档、复杂状态机或自动化游戏测试。语法检查成功不等于游戏逻辑已通过全面测试。

## V24：自动存档与恢复

### 存储结构
- Key：`moonlitKeepSaveV25`；顶层 `version: 25`。键位设置仍使用原来的 `moonlitKeepKeyMap`，两者互不覆盖。
- `player` 保存角色位置、当前/最大生命与灵力、等级、经验、升级阈值、属性点、攻击/防御加点及朝向。
- `inventory` 保存金币、药水、合法装备 ID、已开启宝箱坐标；`equipment` 保存各装备槽位 ID。
- `world` 保存战利品计数、击败数量、Boss 是否现身/存活/阶段、胜负状态、敌人列表、Boss 位置与生命、掉落物及镜头位置。

### 保存触发
- 游戏运行中每 5 秒检查一次；暂停、页面隐藏/离开、开宝箱、拾取、分配属性点、更换装备、角色倒下和击败 Boss 时即时保存。
- 演示模式不写入存档，避免演示过程污染玩家进度。
- `localStorage` 写入失败会在页眉状态按钮提示，不阻断游戏运行。

### 安全恢复
- 仅接受版本号匹配、核心对象和数组类型正确的存档。
- 数值经有限范围裁剪；装备 ID、敌人类型、装备槽位和宝箱坐标均需通过白名单验证。
- 不从存档恢复可执行代码、HTML 或任意对象原型；敌人、掉落物按受控字段重建。
- 暂时不恢复实时飞行中的投射物、敌人瞬时受击闪烁、角色无敌帧和 Boss 冲刺/范围攻击计时器；恢复时将这些瞬态状态重置，以避免不稳定状态。
- 存档只在当前浏览器站点存储内，不支持云端同步或跨设备迁移。用户清除站点数据后无法保证找回。

### 调试
在浏览器开发者工具 Console 中可查看 `localStorage.getItem('moonlitKeepSaveV25')`。请勿把该内容视为可信输入；游戏加载过程会重新校验数据。手动保存按钮可用于即时保存并确认写入结果。
