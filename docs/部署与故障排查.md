# 部署与故障排查

## 1. 发布到 GitHub Pages

### 创建仓库

1. 登录 GitHub 并新建仓库，例如 `moonlit-keep`。
2. 上传项目全部文件，必须保留 `docs/` 目录及其文件。
3. 确认 `index.html`、`manifest.webmanifest`、`sw.js`、`icon.svg` 位于仓库根目录。

### 启用 Pages

1. 打开仓库 **Settings → Pages**。
2. 在 Build and deployment 中选择从分支部署。
3. 选择 `main` 分支和 `/(root)` 目录并保存。
4. 等待 GitHub Pages 发布完成，再打开显示的 HTTPS 地址。

项目仓库 URL 与发布 URL 不一定相同。以 GitHub Pages 页面显示的地址为准，不要手动猜测路径。

## 2. Android 手机安装

1. 用 Android Chrome 打开已发布的 HTTPS 网站。
2. 首次访问保持联网，等待游戏加载及 Service Worker 安装。
3. 打开 Chrome 菜单，选择“安装应用”或“添加到主屏幕”。不同系统/浏览器版本的菜单文字可能不同。
4. 推荐横屏游玩；如果没有安装选项，仍可通过浏览器直接游玩。

PWA 安装通常要求 HTTPS 或 localhost。通过文件管理器直接打开 `file://` 的 HTML 文件，不适合作为完整 PWA 部署方式。

## 3. 更新后仍显示旧版

项目的 Service Worker 使用缓存名 `moonlit-keep-v2`。更新游戏静态资源时，应将 `sw.js` 的缓存名递增，例如改为 `moonlit-keep-v3`，再提交并发布。

如果网页仍旧：

1. 确认 GitHub Pages 发布完成，并检查线上 `index.html` 是否已更新。
2. 关闭游戏页面后重新打开并刷新。
3. 在 Chrome 网站设置中清理该站点的缓存/存储数据，再重新访问。
4. 若已安装为应用，必要时移除主屏幕快捷方式/已安装应用，再重新从网站安装。
5. 先在线打开一次，确认新版本正常后再测试离线。

清除站点数据可能会移除该站点保存的数据；当前版本没有持久化游戏存档，但仍建议确认后再执行。

## 4. 常见问题

### 页面空白或没有游戏画面

- 确认打开的是 `index.html` 对应的发布地址。
- 检查浏览器开发者工具 Console 是否有 JavaScript 错误。
- 检查文件上传是否完整，特别是 `index.html` 是否被截断。
- 如果刚改过代码，先做语法检查，再逐步撤回最近的改动定位问题。

### 按键无响应或角色一直移动

- 测试键盘时检查 `keydown` 和 `keyup` 是否都能触发。
- 触屏按钮使用 Pointer Events；检查 `pointerup`、`pointercancel` 和窗口失焦清理逻辑。
- 尝试刷新页面并重新进入游戏。
- 检查按钮上是否存在遮挡层，或 CSS 的 `pointer-events`/`touch-action` 是否被修改。

### 挥鞭看得到，但敌人不掉血

- 确认敌人与玩家在同一世界坐标附近，而不只是屏幕位置接近。
- 检查 `attackHitbox()` 有效帧窗口和攻击盒范围。
- 检查玩家朝向 `face`，以及敌人 `alive` 状态。
- 记住 Canvas 绘制坐标通常会减去 `camera`，但碰撞坐标不应该减去 `camera`。

### 手机上显示比例或按钮不正常

- 先横屏测试，关闭浏览器缩放或系统放大设置进行对照。
- 不同屏幕比例会改变 Canvas 的 CSS 尺寸，但逻辑分辨率仍为 480×270。
- 检查 `viewport`、`100dvh`、安全区 `env(safe-area-inset-bottom)` 和媒体查询。
- 语法检查不能代替真实设备测试；修改后应至少在目标手机上实际操作。

### PWA 安装按钮没有出现

- 确认网站为 HTTPS，且 manifest 和图标路径可访问。
- 并非所有浏览器或所有访问情境都会触发 `beforeinstallprompt`。
- 可尝试使用浏览器菜单中的“添加到主屏幕”。
- 这只是演示级 PWA 配置；浏览器安装条件可能随版本变化。

## 5. 变更后最低验证标准

- [ ] 首页可以加载并进入游戏。
- [ ] 移动、跳跃、挥鞭、灵击正常。
- [ ] 敌人、Boss、HUD、胜负界面正常。
- [ ] Android 横屏触控正常。
- [ ] 新版本缓存名已更新（如果改动静态资源）。
- [ ] GitHub Pages 线上页面已验证，而不只检查本地文件。


## v0.22：Boss 分阶段战斗
- Boss HUD 显示实时生命值与当前阶段。阶段阈值为 66% 和 33%。
- 阶段 I 使用高/低位灵弹；阶段 II 加入冲刺与范围攻击；阶段 III 加快攻击并召唤最多 4 个亡灵援兵。
- Boss 胜利奖励为金币 +100、生命药水 +1、灵力药水 +1，并优先赠送一件尚未收集的装备；随机掉落机制不变。
- 如果更新后仍看到旧版，请关闭已打开的 PWA，再重新打开；必要时清除该站点缓存后重新加载。

## V23 角色成长功能检查
- 击败敌人后打开「查看物品清单」，确认经验值增加；不同敌人经验值不同。
- 累积 100 经验后确认升到 2 级，生命上限增加 10、灵力上限增加 5，并获得 2 点属性点。
- 分别点击「攻击 +1」「防御 +1」，确认属性点扣除、攻击/防御数值变化；无属性点时按钮应禁用。
- 确认 HUD 生命/灵力条、药水恢复、灵击消耗与新上限一致。重新开始会重置成长数据。
- 若浏览器仍显示旧界面，更新 Service Worker 缓存后强制刷新（桌面浏览器 Ctrl+Shift+R）；本版缓存名为 `moonlit-keep-v25`。


## V24 自动存档验证清单

1. 通过 HTTPS 或 localhost 打开游戏，开始新游戏并收集金币/药水或开启一个宝箱。
2. 等待至少 5 秒，或点击页眉「存档」按钮手动保存；状态应显示已保存。
3. 刷新页面，标题页应出现「继续冒险」；点击后检查角色位置、等级、金币、药水、装备和宝箱状态是否恢复。
4. 拾取掉落物后立即刷新，确认同一掉落物不会重复领取。
5. 暂停后刷新，确认暂停前的进度已保存；关闭标签页后重新打开也应能恢复最后一次写入的数据。
6. 在开发者工具中将 `moonlitKeepSaveV25` 改为无效 JSON 或改动版本号，刷新页面；继续入口不应出现，游戏不得因解析异常崩溃。
7. 清除站点存储后刷新，确认可正常开始新游戏，键位设置仍由独立的 `moonlitKeepKeyMap` 管理。
8. PWA 已安装的设备需确认更新后加载 `moonlit-keep-v25` 缓存；必要时关闭旧标签页并重新打开应用。

注意：可先运行 `node tests/v24-regression-check.js` 执行 12 项自动静态/语法检查。浏览器存储权限、PWA 更新时序、Android 触屏及真实设备刷新恢复仍需要按以上步骤人工验证。


## V25 隐藏区域验证清单

1. 从大厅向右探索到钟楼方向与图书馆区域附近的青色隐秘石门（世界坐标约 x=790）。
2. 靠近石门按 ↑，应进入「月影密室」并看到专属环境和额外平台。
3. 从密室左侧石门按 ↑ 返回主古堡。
4. 在密室开启额外宝箱，收集奖励后刷新并继续冒险，确认角色位置和宝箱状态仍保留。
5. 确认浏览器加载 `moonlit-keep-v25` 缓存；若显示旧版，关闭旧标签页并强制刷新。
